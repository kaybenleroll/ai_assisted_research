# GLM Educational Examples

The fixed-design scripts illustrate model construction; they are not general-purpose statistical packages. Real-data inputs and reuse terms are recorded in [the data README](../data/README.txt). Run the manifest from the repository root with `just examples glm`. All numerical fixtures are defined in the scripts; the artificial outcomes do not represent a real field survey. The runner uses the repository's pinned R, Python and Julia containers with networking disabled. It mounts the repository read-only and writes temporary artefacts to `EXAMPLE_OUT`.

- `core.R`, `core.py`, `core.jl`: same four GLMs, same design and two predictions; R's `glm` anchors the small IRLS demonstration in Python and Julia. The independent fixed predictions are checks, not a substitute for comprehensive numerical validation.
- `nb.*`: NB2 with **fixed** theta 2 (variance `mu + mu^2/2`), common exposure and predictions; it does not estimate dispersion.
- `gam.*`: cubic truncated-power basis with one knot and a fixed penalty; R checks the penalised objective against `mgcv`. It illustrates a spline basis, not data-driven smoothing selection or full `mgcv` smooth equivalence. No extrapolation or smooth-interval claim follows.
- `extensions.R`: quasi and estimated NB, `mgcv` REML smooth, quadrature GLMM, zero-inflated/hurdle, ordinal/multinomial and binomial/logistic posterior calculations. Its random-effect integral is shifted to reduce underflow, but this small demonstration has limited numerical robustness and lacks independent software fit and general error guarantees. Zero-model fits are intercept-only and cannot infer mechanism from zeros.
- `bayes.R`: four random-walk Metropolis chains compared with a two-parameter grid and a beta-binomial hierarchy with hypermean grid and exact conditional beta draws. Acceptance and lag-one correlation are limited descriptive checks, not convergence proof; a fixed seed does not establish convergence. Production MCMC needs vetted split-Rhat, effective sample size and other diagnostics, plus prior and posterior predictive checks.

The same inputs and calculations across languages support narrow cross-checks, not interchangeable packages or universal parity. Real data, model robustness, accessible figures, full interpretation and additional numerical checks remain part of primer implementation.

- `ordinal-repair.R`: pre-specified simulated violation of proportional odds, exploratory cumulative slopes and held-out multinomial comparison. One simulation does not establish universal predictive superiority.
- `prepare_data.R`: verifies hashes and input structure, regenerates package-derived salamander CSV into `EXAMPLE_OUT`, and checks the regenerated hash. `real_cases.R` verifies the frozen inputs, fits the documented real penguin and salamander models, checks rank and known numerical values, and writes coefficient, prediction and validation tables to `EXAMPLE_OUT`. Its models and a single grouped split illustrate decisions, not complete inferential validation. Counts are observations, not occupancy; the selected salamander covariate is scaled. The real examples do not use an invented exposure offset.

To run selected entries from the repository root, use `just examples glm bayes-r ordinal-repair-r` or `just examples glm prepare-data-r real-cases-r`. A passing script and known numerical answer do not establish that model assumptions, sampling design, or an ecological conclusion are correct. The deliberately small custom algorithms omit production safeguards; use established, validated software for a substantive analysis.

- `core-repairs.R`: fitted penguin mean and future-observation intervals and nested likelihood test; a four-cell logistic interaction and coefficient covariance; penalised separation; and a Gamma predictive check, revision and held-out re-evaluation. The repaired Gamma model still undercovers in this particular split; the example is not evidence of universal superiority. The separated unpenalised fits deliberately suppress iteration warnings to show coefficient drift, and the bounded penalty objective is not a production-safe optimiser.
- `extensions-bayes-repairs.R`: held-out negative-binomial and mixture count checks, conditional and new-site random-intercept predictions, concurvity and smooth revision, and conjugate Poisson-rate inference with an explicit heterogeneity repair. These are synthetic teaching cases; conditional simulations do not include fitted-parameter uncertainty, and numerical integration and grid methods have the limitations described in the primer.

Run only these cases with `just examples glm core-repairs-r extensions-bayes-repairs-r`.

## Language Coverage of Worked Cases

The table describes tested implementations, not general feature equivalence. R remains the main teaching language. The Python and Julia calculations use the repository's pinned NumPy/SciPy and Julia standard libraries, with ForwardDiff only where explicitly used by the existing spline and NB examples. The manually coded fitting procedures are bounded teaching examples, not replacements for established packages.

| Worked case | R | Python | Julia | Boundary |
|---|---|---|---|---|
| Fixed-design Gaussian, binomial, Poisson offset and Gamma | `core.R` | `core.py` | `core.jl` | Matched response predictions on a benign full-rank design |
| Fixed-dispersion NB2 with offset | `nb.R` | `nb.py` | `nb.jl` | Shape is fixed at 2; this is not estimated-dispersion NB |
| Fixed-penalty cubic spline | `gam.R` | `gam.py` | `gam.jl` | Fixed knot and penalty; not data-driven REML parity |
| Real penguin Gaussian/Gamma species means, contrasts and design rank; salamander GP Poisson | `real_cases.R` | `real_cases.py` | `real_cases.jl` | Same frozen files and complete-case rule; R alone also fits estimated NB and illustrates holdout scores |
| Conjugate Poisson–Gamma count posterior | `extensions-bayes-repairs.R` | `bayes_count.py` | `bayes_count.jl` | Same shape/rate convention and mean, credible and future-count intervals; not a generic Bayesian sampler |
| Quasi, estimated NB, GLMM, REML smooth, hurdle/zero inflation, ordinal and multinomial | `extensions.R`, `extensions-bayes-repairs.R`, `ordinal-repair.R` | Not implemented in these companion examples | Not implemented in these companion examples | The specified substantive teaching cases are R-only; no blanket cross-language equivalence is claimed |
| Logistic posterior grid, MCMC and hierarchical pooling | `bayes.R` | Not implemented in these companion examples | Not implemented in these companion examples | Toy diagnostics and fixed-concentration hierarchy are limited as described above |

The real-data scripts read the same SHA-256-checked inputs. For penguins they retain rows with both mass and species (342 of 344), use Adelie as the reference, compare Gaussian and Gamma species means, and check additive and interaction design ranks. For package-derived salamanders they select the 92 GP records from 23 sites and fit observed count on mining status and scaled `DOP`, using unmined as the reference. The same R predictions at `DOP = 0` are approximately 2.2061 and 0.04550 for unmined and mined groups. These independent-row Poisson fits are descriptive demonstrations; four visits share each site, and they do not identify occupancy, true abundance or causation. The more flexible estimated-dispersion NB, group-held-out and other diagnostics are shown in R rather than silently described as translated.

For the count posterior, twelve observations sum to 28 and the prior is Gamma(shape 2, rate 1). Each implementation produces Gamma(shape 30, rate 13), posterior mean 30/13, a central 95% mean-rate credible interval approximately 1.557–3.204, and a central 95% future-count interval 0–6 using the predictive NB(size 30, success probability 13/14). The interval targets differ. Julia uses an integer-shape Gamma CDF and a discrete negative-binomial probability recurrence, both implemented for this bounded example; its bisection and recurrence are not a general-purpose probability library.

Run the four added checks from the repository root with `just examples glm real-cases-python real-cases-julia bayes-count-python bayes-count-julia`. The R counterparts are `real-cases-r` and `extensions-bayes-repairs-r` in the manifest. These matched checks do not resolve general model adequacy, full independent software validation, or cross-language implementations for the specialised R-only cases.

The combined-model example uses a reproducible simulated survey of 72 independent sites and four visits each, with a known exposure, NB2 counts, a smooth covariate effect and normal site intercepts. The R script fits five prespecified candidates on 54 sites and scores 18 unseen sites only after fitting. `combined-fixture.csv` records one held-out site's fitted inputs and expected outputs from that R fit; `combined.py` and `combined.jl` independently calculate conditional and new-site integrated means and the joint log predictive density on those fixed inputs. They do not refit the models. The shared numerical score integrates one site effect across all four visits, uses fixed fitted parameters, and does not include parameter uncertainty. The random effect set to zero is not the integrated mean; neither is a prediction for a future count. Use `just examples glm combined-r combined-python combined-julia` from the repository root. One simulated split cannot establish comparative superiority or ecological validity.
